# Crypto Pulse

Микросервис котировок BTC, ETH и TON на GitHub Actions: JSON-лента, изменение за сутки и история за 30 дней. Python 3.12, без внешних библиотек, API-ключей и отдельного сервера.

GitHub запускает сборщик примерно каждый час, на 17-й минуте UTC. У GitHub расписание может задерживаться; это сводка для наблюдения за рынком, а не поток для торговли.

## Как пользоваться

- [JSON-сводка](data/latest.json): цены в USD, изменение за 24 часа, время котировок и флаги `up` / `down`, если движение достигло порога.
- [История CSV](data/history.csv): по одной строке на монету и запуск за последние 30 дней. История накапливается с первого запуска, прошлые цены не выдумываются.
- [Читаемая сводка](data/summary.md): также выводится в Summary каждого успешного workflow.

После публикации в `insider22/crypto-pulse-test` открытая ссылка на JSON:

```text
https://raw.githubusercontent.com/insider22/crypto-pulse-test/main/data/latest.json
```

Пример запроса:

```bash
curl -fsSL https://raw.githubusercontent.com/insider22/crypto-pulse-test/main/data/latest.json
```

У GitHub Raw есть кеширование и лимиты. Клиент обязан сравнивать текущее время с `expires_at`, даже если HTTP-ответ успешный: при сбое сборщик сохраняет прошлую успешную сводку. `generated_at` — время сборки, `source_updated_at` — время конкретной цены у CoinGecko. Срок годности считается от самой старой котировки. Цены старше часа, пропущенные монеты, некорректные числа и ошибки API приводят к неуспешному workflow без замены сводки.

`alerts` — отметки в JSON и таблице, а не отправка уведомлений в Telegram или на почту. `change_24h_pct` берётся у провайдера за скользящие 24 часа; оно не вычисляется относительно прошлого запуска.

## Настройка

В `watchlist.json` можно менять монеты (CoinGecko ID, символ и название) и `alert_threshold_pct`. По умолчанию порог — ±5% за сутки. Коммит изменений списка запускает обновление.

Добавление монеты не создаёт историю задним числом. Для тестового сервиса достаточно до 20 монет в одном запросе к бесплатному API. При временных ошибках и HTTP 429 сборщик делает до трёх попыток с ограниченной задержкой.

## Запуск в облаке

1. Создать пустой **публичный** репозиторий `crypto-pulse-test`. Не добавлять README, `.gitignore` или лицензию в форме создания.
2. Загрузить содержимое проекта в ветку `main`, включая `.github/workflows/refresh.yml`.
3. Открыть вкладку **Actions** → **Refresh crypto feed**. Первый запуск стартует от push; можно также нажать **Run workflow**.

Workflow запрашивает только `contents: write` для коммитов данных. Доступы к кошелькам, биржам и пользовательские секреты не нужны. В публичных репозиториях стандартные GitHub-hosted runners предоставляются бесплатно в рамках правил GitHub. Если настройки аккаунта ограничивают Actions, нужно разрешить запуск workflow и запись содержимого.

Создать репозиторий с GitHub CLI и отправить уже подготовленный проект:

```bash
git init -b main
git add .
git commit -m 'feat: add hourly crypto price feed'
gh repo create insider22/crypto-pulse-test --public --source=. --remote=origin --push
```

Для уже созданного пустого репозитория вместо последней команды:

```bash
git remote add origin https://github.com/insider22/crypto-pulse-test.git
git push -u origin main
```

Расписание работает только для workflow в ветке по умолчанию; здесь предполагается `main`. GitHub может отключить расписания публичного репозитория после 60 дней отсутствия активности. Проверять состояние можно во вкладке Actions; включить заново — там же.

## Локальная проверка

```bash
python3 -m unittest discover -s tests -v
python3 src/crypto_pulse.py
python3 -m http.server 8000 --bind 127.0.0.1
# GET http://127.0.0.1:8000/data/latest.json
```

Тесты не используют сеть. Команда сборки делает настоящий запрос к [CoinGecko Public API](https://docs.coingecko.com/reference/simple-price). Данные предназначены для наблюдения, без торговых команд, кошельков и подписания транзакций.
